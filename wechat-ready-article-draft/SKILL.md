# 微信成稿直排

## 概述

在保证原意稳定的前提下，把输入文本整理成可直接发布的中文文章。
默认输出精炼、顺畅、结构清晰的成品文案，不夹带过程说明。
默认基于“开篇抓手 + 全文主线”生成一个可发布的最终标题。

## 执行流程

1. 先判断输出模式。
- `预览 + 成稿`：先给简短文章预览，再给完整成稿。
- `仅成稿`：只输出最终文章，不写解释。
- `写入文件`：用户明确说“输出到文件”时，落到本地文件。
- 非明确要求时，不输出 HTML/CSS。

2. 按“最小改动”原则处理内容。
- 保留核心观点、逻辑顺序和情绪色彩。
- 只删除不影响含义的重复与口语赘余。
- 不新增输入中没有的事实、数据、引用或结论。
- 原文是一人称时，保留一人称叙述。

3. 优化开篇抓手（默认启用，优先“反常现象”）。
- 开篇优先级：`反常现象` > `共鸣场景` > `价值承诺`。
- 若原文里存在可提炼的反常现象，第一段优先写它，用于激发“为什么会这样”的好奇心。
- 推荐开篇三步：
`反常现象句`：指出一个违背直觉的事实或感受；
`追问句`：把读者带入问题（为什么会这样/这意味着什么）；
`价值承诺句`：明确本文将探索什么、回答什么。
- 可用三种开篇动作：
`反常现象`：抛出违背常识或经验反差；
`共鸣场景`：让读者迅速代入“这就是我”；
`认知缺口`：指出读者尚未命名的问题或盲点；
`价值承诺`：明确读完后能获得什么理解或答案。
- 前 3 段避免平铺直叙，避免“今天聊聊”“我想说说”这类弱开头。
- 禁止在正文里出现“抓手/开篇抓手/反常现象开头/下面我来讲”等写作过程提示语。
- 开头直接给读者可感知的内容，不解释所用写作技巧。
- 禁止使用“一个反常现象是”“先说一个反常现象”“这里有个反常现象”等套路提示句开头。
- 反常现象应被自然写进叙述本身，而不是被标签化说明。

4. 生成最终标题（默认启用）。
- 标题先对齐首段抓手，再覆盖全文主线，确保“开头提出的问题”与“正文给出的回答”是同一件事。
- 标题提炼顺序：`反常现象/核心冲突` + `讨论对象` + `价值落点`。
- 用户已给标题时，优先保留其方向；若原标题过泛、过长或牵引力不足，可在不改变原意前提下提炼和升华为最终标题。
- 标题避免空泛大词与夸张承诺，避免“震惊/颠覆/必看”等标题党表达。
- 默认只输出一个最终标题，不并列多个候选。

5. 组织为可发布结构。
- 优先继承用户标题方向，并使用上一步产出的最终标题作为 H1。
- 使用自然小标题，不使用“说明性标签”。
- 默认强制输出段落标题；除非用户明确要求“不要小标题”。
- 标题数量与正文结构一致，通常为 3-6 个二级标题。
- 段落短而清晰，便于阅读与发布。
- 衔接自然，整体读感连贯。

6. 输出前做成品化检查。
- 删除“成稿说明”“预览说明”“过程解释”等元文本。
- 删除占位符和脚手架标记。
- 删除所有写作方法提示语（例如“先说一个反常现象”“为了抓住注意力”）。
- 检查是否包含二级标题；若缺失则补齐后再输出。
- 检查首句是否口语化、模板化、标签化；若是则重写首句。
- 检查标题是否与首段抓手和全文主线一致；若不一致则重写标题。
- 确保文本可直接复制发布。

## 输出模板

用户要“预览 + 成稿”时：

```markdown
**文章预览**
[2-4 行，简明具体]

---

# [文章标题]
[成稿正文]
```

用户只要“成稿”时：

```markdown
# [文章标题]
[成稿正文]
```

## 质量标准

- 把“最小改动原意”当作硬约束。
- 开头必须具备“可继续读下去”的牵引力。
- 在可行时，第一段必须出现一个“反常现象”并引出追问。
- 第一段不允许出现对写作技巧的自我说明。
- 标题必须与开篇抓手同题，且能概括全文的核心回答。
- 标题避免模板化、口号化和标题党表达。
- 可读性优先于辞藻堆砌。
- 语言自然、地道，不模板化。
- 最终交付必须是可直接发布的完整稿件。
